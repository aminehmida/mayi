The first alpha of Mayi: your agents ask before they use a secret or sign in as you, and you answer on your own Mac or phone.

**This is an alpha.** Nothing has been audited, and several paths have only been tested with stand-ins for real hardware (see `docs/manual-checks.md`). Do not put secrets in it that you cannot rotate.

## What is in it

- **Secrets for commands.** `mayi run -s GITHUB_TOKEN -r "why" -- gh pr list` injects the value into the command's environment and masks it in the output. The agent never sees it.
- **Website logins.** `mayi fill github -r "why"` types a login into the sign-in page open in the agent's browser, two-factor code included. A login is typed only into its own websites, over https, and never given to a command. The two-factor key never leaves your devices.
- **Four levels per secret.** Log, notify (with Stop), approve, or fingerprint (Touch ID or the phone's sensor, enforced by encryption).
- **Agents anywhere.** A server or VM pairs with your Mac or phone and asks over an encrypted tunnel; nothing is stored there.
- **Several devices.** The Mac app and the Android app sync with each other directly, with no server.
- **For agents:** a skill for Claude Code (`skill/mayi`) and an MCP server (`mayi mcp`).

## Files

| File | For |
|---|---|
| `Mayi-0.1.0-alpha.1-macos-arm64.zip` | The Mac app (Apple silicon, macOS 14 or later), with the `mayi` command inside |
| `mayi-0.1.0-alpha.1-android.apk` | The Android app (Android 12 or later, a phone with secure key storage) |
| `mayi-0.1.0-alpha.1-aarch64-apple-darwin.tar.gz` | The `mayi` command alone, for a Mac without the app |
| `mayi-0.1.0-alpha.1-x86_64-unknown-linux-musl.tar.gz` | The `mayi` command for Linux (static) |
| `mayi-0.1.0-alpha.1-aarch64-unknown-linux-musl.tar.gz` | The same for 64-bit ARM Linux |

Install with Homebrew or Obtainium as described in the README.

## Known limits

- The Mac app is signed ad hoc, not notarized. The Homebrew cask clears the quarantine flag so it opens.
- Apple silicon only on the Mac; no Intel build yet.
- A phone answers only while awake, unless you deploy the wake-up gateway in `services/wake` with your own Firebase project.
- The Android release refuses phones that cannot hold keys in secure hardware, which includes emulators.
