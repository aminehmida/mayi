Tenth alpha: groundwork for credentials Mayi does not simply store (AWS SSO, SSH signing, a token proxy), and a vault that devices on different versions can share.

## Devices on different versions

- **A secret of a kind this version does not know no longer breaks the vault.** Before, one such secret stopped a device from listing its secrets and from syncing at all. Now it is listed and synced, and what this version does not understand about it is kept intact. It is never opened on that device: a request for it is refused, before any prompt, with a message to update Mayi there.
- **Update every device to this version before the next one**, which adds the first new kind of secret (AWS SSO). A device older than this one cannot read a vault that holds one.

## Under the hood

- **Secrets now have a destination and a source**: where the values go (a command, or a website's sign-in form) and what produces them. Each source has a provider, built into Mayi. Stored values and website logins are the first two; a login's two-factor code is now made by its provider. Nothing changes in the vault file, between devices or in the apps.
- **What comes next is planned in [docs/providers.md](../providers.md)**: AWS SSO with the sign-in on your Mac or phone and a level for each role, SSH and git signing with keys that never leave the Secure Enclave, database passwords, a proxy that adds a token to requests without the command ever holding it, then gcloud, Azure and others.

## Updating

Quit Mayi on the Mac, then `brew upgrade --cask mayi`, and allow the keychain prompt when Mayi starts, as after the last update. Update the phone through Obtainium. `mayi` on other machines did not change.
